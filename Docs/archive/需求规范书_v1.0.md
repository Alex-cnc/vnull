## 1. 项目概述

### 1.1 背景

团队需要同时访问 **PostgreSQL**（主要）与 **GBase 8a**（南大通用，MySQL 协议系）两类数据库。现有图形化客户端要么只支持单一数据库，要么体积庞大、需要 Java 运行时、或对国产数据库支持不足。因此自建一个 macOS 原生、轻量、可控的数据库客户端。

工程最初按「需求分析与概要设计 v1.2」搭建骨架，现已完成 PostgreSQL 全链路（连接 → 执行 → 元数据 → 结果展示）的可运行版本。

### 1.2 产品目标

1. **原生体验**：SwiftUI + AppKit 混合，macOS 14+，Apple Silicon 原生运行，无 JVM / 无 Electron。
2. **PostgreSQL 优先**：先把 PostgreSQL 做到「能日常用」，再扩展 GBase 8a。
3. **双库统一交互**：同一套 UI、同一套快捷键，通过方言层适配差异，用户不必学两套操作。
4. **可验证**：核心逻辑（拆分、方言、静态检查、配置序列化）必须有单元测试；连接链路必须有命令行可验证手段。
5. **可扩展**：新增数据库类型 = 新增 `DatabaseService` 实现 + 新增 `SQLDialect` 实现，UI 层零改动。

### 1.3 范围

**本期（v1.x）范围内**

- 连接配置的增删改查、密码安全存储、连接测试
- PostgreSQL 真实连接、SQL 执行、多语句拆分、结果集展示
- 元数据对象树（懒加载）
- SQL 编辑器（语法着色、客户端静态检查、服务器端 EXPLAIN 检查）
- 结果集复制（TSV）、列宽调整、列重排、多选
- 命令行工具（无 UI 验证链路）
- GBase 8a 的方言层（SQL 文本生成、语句拆分）——已实现
- GBase 8a 的驱动层（`GBaseService` + `GBaseMetadataService`）——排期最后

**本期范围外（明确不做）**

- 数据库对象的管理操作（建库、建表、建用户、授权）——只读元数据浏览
- 数据建模 / ER 图 / 数据字典导出
- 数据同步、迁移、批量导入工具
- Windows / Linux 客户端，iOS / iPadOS 版本
- 多人协作、云端配置同步
- 遥测、崩溃上报、任何形式的数据外发

### 1.4 目标用户

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 后端 / 数据开发 | 日常写 SQL、查数据 | 快速连库、快捷执行、结果可复制进 Excel |
| DBA / 运维 | 关注版本、对象结构 | 对象树浏览、错误信息准确 |
| 数据分析 | 写复杂查询 | 多结果集、耗时可见、语法预检 |

### 1.5 运行环境与技术约束

| 项 | 要求 |
|---|---|
| 操作系统 | macOS 14.0（Sonoma）及以上 |
| 架构 | Apple Silicon（arm64）；Intel 兼容 |
| 语言 | Swift 5.10 |
| UI | SwiftUI 为主，`NSTextView` / `NSTableView` 桥接 |
| 工程生成 | XcodeGen（`project.yml` → `PostgresClient.xcodeproj`） |
| 依赖 | PostgresNIO 1.33.1（源码内置于 `Vendor/postgres-nio`，Xcode 引用本地包） |
| 打包 | Xcode 构建，或 `Scripts/build-app.sh` 走 SwiftPM 组装 `.app` + ad-hoc 签名 |
| 沙箱 | App Sandbox：`network.client`、`files.user-selected.read-write`；Hardened Runtime 开启 |
| 最低依赖 | 不引入除 PostgresNIO 及其传递依赖外的第三方库 |

### 1.6 假设与依赖

- A1：目标 PostgreSQL 服务器允许客户端 IP 直连（`pg_hba.conf` 放行）。
- A2：密码由用户自行保管；App 不做密码找回。
- A3：GBase 8a 服务端的认证插件、版本号格式、`DELIMITER` 行为需先用 `mysql` 客户端实测确认（见 9. 风险）。
- A4：国内网络下 GitHub 依赖可能不可达，依赖 `Scripts/setup-package-mirrors.sh` 与本地 Vendor 包。
- A5：命令行构建环境需 `DEVELOPER_DIR` 指向 Xcode；SwiftUI 宏在受限环境下需要 `-Xfrontend -disable-sandbox`。

## 2. 产品总体描述

### 2.1 产品形态

单窗口 macOS 应用：左侧导航分栏（连接列表 + 元数据对象树），右侧查询工作区（多页签 SQL 编辑器 + 结果表格）。另附一个命令行工具用于无 UI 验证。

### 2.2 架构分层

```
┌──────────────────────────────────────────────┐
│ App 层（SwiftUI + AppKit 桥接）              │
│  MainWindow / ConnectionListView /           │
│  QueryWorkspaceView / SQLEditorView /        │
│  ResultTableView / ObjectTreeView            │
├──────────────────────────────────────────────┤
│ 状态层  AppState（@MainActor, Observable）   │
│  连接缓存 / 页签管理 / 执行编排 / 取消        │
├──────────────────────────────────────────────┤
│ 服务层（PostgresClientCore.framework）        │
│  DatabaseService（协议）  MetadataService     │
│  SQLDialect（协议）       StatementSplitter   │
│  SQLTokenizer / SQLLinter / ConnectionStore   │
│  SecretStore(Keychain)    AppError            │
├──────────────────────────────────────────────┤
│ 驱动层                                       │
│  PostgresService(PostgresNIO)                │
│  NotImplementedDatabaseService(GBase 占位)    │
└──────────────────────────────────────────────┘
```

**设计原则（强约束）**

1. **协议层与方言层分离**：驱动只负责传输，SQL 文本一律由 `SQLDialect` 生成；`MetadataService` 只做「结果行 → 领域对象」的映射。
2. **UI 不感知驱动细节**：UI 只依赖 `DatabaseService` 协议。
3. **Core 可单测**：`Core/` 不 import SwiftUI/AppKit，全部逻辑可在 SwiftPM 下测试。

### 2.3 模块划分

| 模块 | 目标 | 关键文件 |
|---|---|---|
| 配置与安全 | 连接配置持久化、密码存储 | `ConnectionConfig.swift`、`ConnectionStore.swift`、`KeychainHelper.swift` |
| 驱动与方言 | 连接、执行、SQL 文本生成 | `DatabaseService.swift`、`PostgresService.swift`、`Dialects.swift`、`DatabaseType.swift` |
| SQL 处理 | 语句拆分、词法着色、静态检查 | `StatementSplitter.swift`、`SQLTokenizer.swift`、`SQLLinter.swift` |
| 元数据 | 对象树懒加载 | `MetadataService.swift`、`QueryModels.swift` |
| 结果处理 | 单元格格式化 | `PostgresCellFormatter.swift`、`PostgresCellFormatter` 调用方 `PostgresService` |
| UI | 窗口、表单、编辑器、表格、对象树 | `App/Views/*`、`App/AppState.swift` |
| 命令行 | 链路验证、批量执行 | `CLI/main.swift` |
| 工程化 | 构建、测试、依赖镜像 | `Scripts/*`、`project.yml`、`Package.swift` |

### 2.4 主要用例

| 编号 | 用例 | 主流程 |
|---|---|---|
| UC-01 | 新建连接并测试 | 连接列表「+」→ 填表 → 测试连接 → 显示版本/库/用户 → 保存 |
| UC-02 | 编辑连接 | 选中连接 → 编辑 → 改字段（密码留空则不改）→ 保存 |
| UC-03 | 删除连接 | 选中 → 删除 → 同时删除 Keychain 密码与缓存连接 |
| UC-04 | 执行单条查询 | 输入 SQL → ⌘↩ → 结果表格显示 |
| UC-05 | 执行多条语句 | 分号分隔 → 逐条执行 → 下拉切换多个结果集 |
| UC-06 | 中途取消 | 执行中点「停止」→ 状态显示「已取消」 |
| UC-07 | 语法预检 | 点「检查」→ 对可 EXPLAIN 语句发 `EXPLAIN` → 显示通过/失败 |
| UC-08 | 浏览对象结构 | 展开对象树节点 → 懒加载下一层 → 查看列类型 |
| UC-09 | 复制结果 | 选中行 → ⌘C → TSV 文本 → 粘贴进 Excel |
| UC-10 | 无 UI 验证 | 命令行 `--tree --columns` / `-c "SQL"` |

## 3. 功能需求

### 3.1 连接管理（FR-CONN）

| 编号 | 需求 | 优先级 | 状态 | 验收要点 |
|---|---|---|---|---|
| FR-CONN-01 | 以列表展示全部已保存连接，可选中，选中项作为后续执行/元数据的上下文 | 高 | ✅ | 重启 App 后列表与选中项可恢复 |
| FR-CONN-02 | 新建连接：名称、数据库类型、主机、端口、数据库名、用户名、SSL 模式、超时 | 高 | ✅ | 端口缺省按类型自动填（PG 5432 / GBase 5258） |
| FR-CONN-03 | 数据库类型切换时，默认端口、默认 SSL 模式、默认 schema 自动联动 | 中 | ✅ | 切换类型后表单值符合 `DatabaseType.defaultPort` 等规则 |
| FR-CONN-04 | 编辑连接：不得出现「点编辑却弹出新建、字段为空」 | 高 | ✅ | 使用 `.sheet(item:)` 绑定具体配置对象 |
| FR-CONN-05 | 删除连接：需二次确认，并同时清理 Keychain 密码与连接缓存 | 高 | ✅ | 删除后 Keychain 无残留项，`services` 缓存已失效 |
| FR-CONN-06 | 配置校验：名称、主机、端口（1–65535）、用户名非空 | 高 | ✅ | 非法输入不允许保存（`ConnectionConfig.isValid`） |
| FR-CONN-07 | 密码存入系统 Keychain，不写入配置文件 | 高 | ✅ | `connections.json` 中不含任何密码字段 |
| FR-CONN-08 | 编辑连接时密码留空 = 保持原密码不变 | 中 | ✅ | 留空保存后旧密码仍可用于连接 |
| FR-CONN-09 | 「测试连接」按钮真实连接服务器，返回 `server_version` / 当前库 / 当前用户 | 高 | ✅ | 断开网络或错误密码时给出可读错误 |
| FR-CONN-10 | 连接配置带 `schemaVersion`，为将来配置格式升级预留迁移能力 | 低 | ✅ | 字段存在且默认 1 |

### 3.2 查询执行（FR-EXEC）

| 编号 | 需求 | 优先级 | 状态 | 验收要点 |
|---|---|---|---|---|
| FR-EXEC-01 | 按当前连接执行 SQL，支持多语句 | 高 | ✅ | 用 `;` 分隔的 `CREATE/INSERT/SELECT` 全部执行 |
| FR-EXEC-02 | 字符串、注释、dollar-quote 内的分号不得触发拆分 | 高 | ✅ | 单元测试与本地链路脚本均覆盖 |
| FR-EXEC-03 | 每条语句按顺序执行，逐条上报执行状态 | 中 | ✅ | 状态栏显示「正在执行第 N 条语句」 |
| FR-EXEC-04 | 多结果集：全部保留，可通过下拉选择器切换查看 | 中 | ✅ | 两个 SELECT 产生两个可选结果集 |
| FR-EXEC-05 | 显示行数 × 列数与单条语句耗时 | 中 | ✅ | 状态栏文案包含行/列/耗时（秒，3 位小数） |
| FR-EXEC-06 | 显示 SQL 错误详情，可选中复制；错误不导致 App 崩溃 | 高 | ✅ | 错误文案出现在编辑器下方，含服务器原始消息 |
| FR-EXEC-07 | 执行中的页签不可关闭 | 中 | ✅ | 关闭按钮无效或被拦截 |
| FR-EXEC-08 | 「停止」取消当前执行 | 中 | 🟡 | 客户端 Task 取消已生效；**服务器端 CancelRequest 未实现** |
| FR-EXEC-09 | 同一连接的并发执行复用同一个连接，避免重复握手 | 中 | ✅ | `connectTasks` 去重逻辑 |
| FR-EXEC-10 | 执行返回「影响行数」（DML command tag） | 低 | ⬜ | 受 PostgresNIO 流式 API 限制，暂不暴露 |
| FR-EXEC-11 | 提供事务 API：`beginTransaction` / `commit` / `rollback` | 低 | 🟡 | 协议与 PostgreSQL 实现已就绪，UI 尚未提供入口 |
| FR-EXEC-12 | 空 SQL 或未选连接时给出明确提示而非静默失败 | 中 | ✅ | 提示「SQL 不能为空」/「请先在左侧选择一个连接」 |

### 3.3 SQL 编辑器（FR-EDIT）

| 编号 | 需求 | 优先级 | 状态 | 验收要点 |
|---|---|---|---|---|
| FR-EDIT-01 | 多页签：新建、切换、关闭；至少保留一个页签 | 高 | ✅ | 关闭最后一个页签的操作被拒绝 |

| FR-EDIT-03 | 客户端静态检查：未闭合字符串、未闭合块注释、未闭合 dollar-quote、括号不配平 | 高 | ✅ | 红色虚下划线 + 提示条 |
| FR-EDIT-04 | 静态检查基于当前方言的关键字与函数表 | 中 | ✅ | 切换数据库类型后关键字集合随之变化 |
| FR-EDIT-05 | 服务器端语法检查：「检查」按钮对可 EXPLAIN 的语句执行 `EXPLAIN`，不真正执行 DML | 高 | ✅ | 只对 `SELECT/INSERT/UPDATE/DELETE/WITH/VALUES/TABLE` 开头语句执行，其余计入「跳过」 |

| FR-EDIT-07 | 修改 SQL 后清空上一次检查结果 | 低 | ✅ | 编辑后提示条消失 |
| FR-EDIT-08 | 执行按钮为绿色实心三角形 ▶，快捷键 ⌘↩ | 中 | ✅ | 快捷键与按钮行为一致 |
| FR-EDIT-09 | SQL 自动补全（关键字 + 内建函数） | 中 | 🟡 | `SQLCompleter` 工具类已实现，**尚未接入编辑器交互** |
| FR-EDIT-10 | 查询历史（按连接记录，可回填） | 中 | ⬜ | `QueryHistory` 数据模型已定义，功能未实现 |
| FR-EDIT-11 | 密码/敏感字段输入使用 ASCII 安全字段，避免输入法干扰 | 低 | ✅ | `SecureASCIIField` |

## 5. 数据需求

### 5.1 连接配置（本地文件）

- 位置：`~/Library/Application Support/PostgresClient/connections.json`
- 格式：JSON 数组，`prettyPrinted + sortedKeys`，日期 ISO8601，原子写
- 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键，同时作为 Keychain account |
| name | String | 显示名 |
| dbType | String | `postgresql` / `gbase8a` |
| host | String | 主机 |
| port | Int | 端口 |
| database | String | 数据库名 |
| username | String | 用户名 |
| sslMode | String | 六种 SSL 模式之一 |
| timeout | Int | 秒 |
| schemaVersion | Int | 配置格式版本，当前 1 |

### 5.2 凭据（Keychain）

| 项 | 值 |
|---|---|
| class | `kSecClassGenericPassword` |
| service | App bundle identifier（默认 `com.fengye.PostgresClient`）|
| account | 连接 UUID 字符串 |
| value | 密码 UTF-8 |

### 5.3 运行期数据（内存）

- `QueryTab`：页签标题、SQL 文本、结果集数组、选中结果索引、执行中标志、状态文案、错误文案、检查结果、来源连接 ID
- `QueryResult`：列元信息（名称/类型/可空）、行数据（`String?` 二维数组）、影响行数、耗时、notice
- `DatabaseObject`：对象树节点（id / 名称 / 类型 / 次要信息 / 子节点）
- `ServerInfo`：版本号、当前库、当前用户

### 7.2 功能验收要点（摘要）

- **连接**：新增 → 保存 → 重启 App 仍在；删除后 Keychain 无残留。
- **执行**：`SELECT 1 AS a; SELECT now();` 产生 2 个结果集，可切换，状态栏显示语句数与总耗时。
- **拆分**：`SELECT ';' AS s;` 只产生 1 条语句。
- **静态检查**：`SELECT 'abc` 有红色提示；`SELECT (1` 提示括号不配平。
- **EXPLAIN 检查**：`SELECT * FROM 不存在的表` 报错；`UPDATE t SET x=1` 只做计划不落库。
- **对象树**：`public` schema 下的表可展开到列，列带类型；系统 schema 不出现。
- **结果复制**：选中 3 行 ⌘C 后粘贴到 Excel 为 3 行 × N 列。
