## 1. 项目概述

### 1.1 背景

团队需要同时访问 **PostgreSQL**（主要）与 **GBase 8a**（南大通用，MySQL 协议系）两类数据库。现有图形化客户端要么只支持单一数据库，要么体积庞大、依赖 Java 运行时、或对国产数据库支持不足。因此自建一个 macOS 原生、轻量、可控的数据库客户端。

工程最初按《需求分析与概要设计 v1.2》搭建骨架，现已完成 PostgreSQL 全链路（连接 → 执行 → 元数据 → 结果展示 → 编辑辅助）的可运行版本。

### 1.2 产品目标

1. **原生体验**：SwiftUI + AppKit 混合，macOS 14+，Apple Silicon 原生运行，无 JVM / 无 Electron。
2. **PostgreSQL 优先**：先把 PostgreSQL 做到「能日常用」，再扩展 GBase 8a。
3. **双库统一交互**：同一套 UI、同一套快捷键，通过方言层适配差异，用户不必学两套操作。
4. **可验证**：核心逻辑（拆分、方言、静态检查、词法着色、配置序列化）必须有单元测试；连接链路必须有命令行与本地脚本验证手段。
5. **可扩展**：新增数据库类型 = 新增 `DatabaseService` 实现 + 新增 `SQLDialect` 实现，UI 层零改动。

### 1.3 范围

**本期（v1.x）范围内**

- 连接配置增删改查、密码安全存储、连接测试
- PostgreSQL 真实连接、SQL 执行、多语句拆分、多结果集
- 工作区上下文栏：当前服务器 / 当前数据库选择，数据库列表按登录用户权限过滤（FR-CONN-12、FR-CONN-13）
- 元数据对象树（懒加载，支持 Database → Schema → Table/View → Column 持续下钻）
- SQL 编辑器（语法着色、客户端静态检查、服务器端 EXPLAIN 检查）
- SQL 编辑区与结果区之间可拖拽分隔（FR-EDIT-13）
- 查询 SQL 的保存与回填（FR-EDIT-14）
- 界面语言中 / 英切换（NFR-I18N-03）
- 查询文件：打开 SQL / 文本文件到新页签（默认不绑定连接）、保存 / 另存为（FR-EDIT-15、FR-EDIT-16）
- 编辑菜单：查找 / 替换、跳到行 / 列、缩进、清除查询、格式化 SQL（FR-EDIT-17 ~ FR-EDIT-22）
- 帮助入口占位（FR-EDIT-23）- 结果表格（`NSTableView`、列宽调整、列重排、多选、TSV 复制）
- 命令行工具（无 UI 验证链路）
- GBase 8a 方言层（SQL 文本生成、语句拆分）——已实现
- GBase 8a 驱动层（`GBaseService` + `GBaseMetadataService`）——排期最后

**本期范围外（明确不做）**

- 数据库对象管理操作（建库、建表、建用户、授权）——只读元数据浏览
- 数据建模 / ER 图 / 数据字典导出
- 数据同步、迁移、批量导入工具
- Windows / Linux 客户端，iOS / iPadOS 版本
- 多人协作、云端配置同步
- 遥测、崩溃上报、任何形式的数据外发

### 1.4 目标用户

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 后端 / 数据开发 | 日常写 SQL、查数据 | 快速连库、快捷执行、结果可复制进 Excel |
| DBA / 运维 | 关注版本、对象结构 | 对象树浏览、错误信息准确 |
| 数据分析 | 写复杂查询 | 多结果集、耗时可见、语法预检 |

### 1.5 运行环境与技术约束

| 项 | 要求 |
|---|---|
| 操作系统 | macOS 14.0（Sonoma）及以上 |
| 架构 | Apple Silicon（arm64）；Intel 兼容 |
| 语言 | Swift 5.10 语言模式（Xcode 27 工具链） |
| UI | SwiftUI 为主，`NSTextView` / `NSTableView` 桥接 |
| 工程生成 | XcodeGen（`project.yml` → `PostgresClient.xcodeproj`） |
| 依赖 | PostgresNIO 1.33.1（源码内置于 `Vendor/postgres-nio`，Xcode 引用本地包） |
| 打包 | Xcode 构建，或 `Scripts/build-app.sh` 走 SwiftPM 组装 `.app` + ad-hoc 签名 |
| 沙箱 | App Sandbox：`network.client`、`files.user-selected.read-write`；Hardened Runtime 开启 |
| 最低依赖 | 不引入除 PostgresNIO 及其传递依赖外的第三方库 |

### 1.6 假设与依赖

- **A1**：目标 PostgreSQL 服务器允许客户端 IP 直连（`pg_hba.conf` 放行客户端网段）。
- **A2**：密码由用户自行保管；App 不做密码找回。
- **A3**：GBase 8a 服务端的认证插件、版本号格式、`DELIMITER` 行为需先用 `mysql` 客户端实测确认（见 R-04）。
- **A4**：国内网络下 GitHub 依赖可能不可达，依赖 `Scripts/setup-package-mirrors.sh` 与本地 Vendor 包。
- **A5**：命令行受限环境构建时需 `DEVELOPER_DIR` 指向 Xcode，并需要 `-Xfrontend -disable-sandbox` / 模块缓存路径等参数（见 10.4）。

## 2. 产品总体描述

### 2.1 产品形态

单窗口 macOS 应用：左侧导航分栏（连接列表 + 元数据对象树），右侧查询工作区（多页签 SQL 编辑器 + 结果表格）。另附命令行工具用于无 UI 验证。

### 2.2 架构分层

```
┌────────────────────────────────────────────────────┐
│ App 层（SwiftUI + AppKit 桥接）                    │
│  MainWindow / ConnectionListView / ConnectionForm  │
│  QueryWorkspaceView / SQLEditorView / ResultGrid   │
│  ResultTableView / ObjectTreeView                  │
├────────────────────────────────────────────────────┤
│ 状态层  AppState（@MainActor, ObservableObject）   │
│  连接缓存 / 页签管理 / 执行编排 / 取消 / 元数据加载 │
├────────────────────────────────────────────────────┤
│ 服务层（PostgresClientCore.framework）              │
│  DatabaseService（协议）   MetadataService          │
│  SQLDialect（协议）        StatementSplitter        │
│  SQLTokenizer / SQLLinter  ConnectionStore          │
│  SecretStore(Keychain)     AppError                 │
├────────────────────────────────────────────────────┤
│ 驱动层                                             │
│  PostgresService(PostgresNIO)                      │
│  NotImplementedDatabaseService(GBase 占位)          │
└────────────────────────────────────────────────────┘
```

**设计原则（强约束）**

1. **协议层与方言层分离**：驱动只负责传输；SQL 文本（含元数据查询）一律由 `SQLDialect` 生成；`MetadataService` 只做「结果行 → 领域对象」映射。
2. **UI 不感知驱动细节**：UI 只依赖 `DatabaseService` 协议与 Core 模型。
3. **Core 可单测**：`Core/` 不 import SwiftUI / AppKit，全部逻辑可在 SwiftPM 下测试。
4. **拆分器不改写 SQL**：`StatementSplitter` 只识别语句边界，语句原文原样发送（`END$` 与 `END $` 必须保持原样）。

**PostgreSQL 特有 vs 跨库通用**

| 类别 | 说明 |
|---|---|
| 依赖 PG 服务端对象 | 会话监控与取消（`pg_stat_activity` / `pg_cancel_backend` / `pg_terminate_backend`）、慢查询（`pg_stat_statements`，需 `shared_preload_libraries` + `compute_query_id` + 读权限）、执行计划的 `FORMAT JSON`（pgAdmin 图形化计划即基于它）、DDL 反查（`pg_get_viewdef` / `pg_get_functiondef`）、`COPY` 与 `pg_dump` |
| 权限裁剪是常态 | 普通用户只能看到自己会话的完整列；终止他人后端需 `pg_signal_backend`。因此 FR-SESS-02 必须按权限呈现动作（R-20），不能假设「有菜单就能杀」 |
| 跨库通用 | 连接分组 / 着色、SSH、SSL、连接 URL、保活；对象浏览与搜索、表浏览过滤、外键跳转、值编辑器；事务模式、格式化、运行范围、查询参数；多格式导出、聚合视图、客户端排序筛选；内联编辑与变更预览、导入映射、可更新结果集；表设计器、DDL 查看、Schema diff、ERD；命令面板、主题、多光标、剪贴板多格式 |

**macOS 沙箱带来的取舍（决定 FR-IO-04 / FR-CONN-18 的架构）**

| 能力 | 沙箱下的约束与结论 |
|---|---|
| 出站 TCP | 需要 `com.apple.security.network.client`；当前 entitlements 已具备，数据库直连不受影响 |
| 调用 `pg_dump` / `pg_restore` / `ssh` | **子进程继承父沙箱**，「包 UI + 起进程」在沙箱版上不可行。三条路线：① 应用内自实现（`COPY … TO STDOUT` 流式导出、纯 Swift 隧道）；② 生成命令交给用户终端执行；③ 改走 Developer ID 非沙箱分发。**必须先选型（R-18 / T-38）** |
| 写任意路径 | 只能写容器内或用户经 `NSOpenPanel` 授权的路径；备份到自选目录建议配 security-scoped bookmark |
| 大结果导出 | 流式落盘与「先全量入内存」是成本分界点（商业客户端也常把「Run To File」放在付费档），对应 FR-IO-02 / FR-RES-13 |
