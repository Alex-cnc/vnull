## 1. 设计目标与约束

| 目标 / 约束 | 说明 |
|---|---|
| 协议层与方言层严格分离 | `DatabaseService` 只负责协议传输；所有 SQL 文本由 `SQLDialect` 生成。新增数据库类型不改 UI（NFR-MAINT-02） |
| Core 可单测 | `Core/` 不 import SwiftUI / AppKit，可在 SwiftPM 下一条命令跑完全部单测（NFR-MAINT-01） |
| 事件流驱动 UI | 执行过程以 `AsyncThrowingStream<QueryEvent>` 暴露，UI 按事件更新状态，不阻塞主线程 |
| 安全与隐私 | 密码只进钥匙串；查询历史不落盘（DR-02）；沙箱最少权限（网络客户端 + 用户选择文件） |
| 可验证 | 每个关键行为都有单测 / 链路脚本 / 手工验收三者之一（AC-REL-01 ~ 08） |

## 2. 总体架构

```
┌────────────────────────────────────────────────────────────────┐
│ 表示层（App/，SwiftUI + AppKit 桥接）                            │
│  MainWindow / ConnectionListView / ObjectTreeView               │
│  QueryWorkspaceView（QueryContextBar + QueryToolbar + 编辑器/结果）│
│  SQLEditorView（NSTextView 桥接）  ResultGrid / ResultTableView   │
└───────────────▲──────────────────────────┬─────────────────────┘
                │ @Published 状态            │ 用户命令
┌───────────────┴──────────────────────────▼─────────────────────┐
│ 应用状态层（App/AppState.swift，@MainActor ObservableObject）     │
│  连接 / 页签 / 结果 / 数据库上下文 / 历史 / 服务缓存 / 任务管理       │
└───────────────▲──────────────────────────┬─────────────────────┘
                │ ServerInfo / QueryEvent   │ SQL 文本
┌───────────────┴───────────┐  ┌───────────▼─────────────────────┐
│ 协议层（Core/…Service）    │  │ 方言层（Core/Dialects.swift）     │
│  DatabaseService 协议      │  │  SQLDialect 协议                 │
│  PostgresService（NIO）    │  │  PostgresDialect / GBaseDialect  │
│  FakeDatabaseService(测试) │  │  语句拆分 StatementSplitter       │
└───────────────────────────┘  └─────────────────────────────────┘
                ▲
                │ 元数据映射
┌───────────────┴────────────────────────────────────────────────┐
│ 服务层 Core/MetadataService（对象树枚举，只依赖 DatabaseService）  │
│ 辅助：SQLTokenizer / SQLLinter / SQLFormatter / SQLCompleter      │
│       ResultExporter / SavedQueryStore / TabNumberGenerator      │
└────────────────────────────────────────────────────────────────┘
```

数据流（执行一次查询）：

```
用户 SQL → AppState.executeQuery
        → StatementSplitter(方言) 拆句
        → DatabaseService.execute(sql, options)  // 事件流
              ├─ .started(index)
              ├─ .resultSet(QueryResult)      // 列元数据 + 行（单元格已格式化）
              ├─ .affectedRows(n)             // DML command tag
              ├─ .notice(message)
              └─ .finished(QuerySummary)
        → AppState 更新 QueryTab（结果 / 状态栏 / 错误）
        → ResultTableView 渲染；导出走 ResultExporter
```

## 3. 模块清单

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `Core/DatabaseService.swift` | 协议：`connect` / `execute` / `cancel` / 事务 / `config` | 只传 SQL 与结果，不生成 SQL |
| `Core/PostgresService.swift` | PostgreSQL 协议实现（PostgresNIO） | 无方言判断；仅本文件 import PostgresNIO |
| `Core/GBaseService.swift`（待实现） | GBase 8a 协议实现（MySQLNIO） | 同上，仅本文件 import MySQLNIO |
| `Core/Dialects.swift` | `SQLDialect` 协议与两个实现、`SQLDialectFactory` | 所有 SQL 文本（库列表、事务、类型名）在此生成 |
| `Core/StatementSplitter.swift` | 分号拆分、dollar-quoting、GBase `DELIMITER` | 不改写 SQL，只切边界 |
| `Core/MetadataService.swift` | 服务器 → 数据库 → schema → 表 → 列 枚举 | 单层懒加载；只依赖 `DatabaseService` + `SQLDialect` |
| `Core/QueryModels.swift` | `QueryEvent` / `QueryResult` / `ColumnMeta` / `DatabaseObject` / `QueryOptions` / `QuerySummary` | 值类型、`Sendable` |
| `Core/PostgresCellFormatter.swift` | 单元格 → 展示字符串（NULL / 二进制 / 日期等） | 纯函数，可单测 |
| `Core/SQLTokenizer.swift` / `SQLLinter.swift` | 词法着色与静态检查 | 诊断文案走 `LKey` |
| `Core/SQLFormatter.swift` | 保守格式化（关键字大写、子句换行、缩进） | 不改 token 内容（gap 原文回填） |
| `Core/ResultExporter.swift` | 结果 → CSV / JSON 文本 | 纯函数，无 AppKit |
| `Core/SavedQueryStore.swift` | 已保存查询 JSON 持久化 | 原子写；不含密码 |
| `Core/Localization.swift` | `AppLanguage` / `LKey` / 中英文案表 | UI 不允许硬编码文案 |
| `Core/EditorTextSync.swift` | 编辑器文本 ↔ SwiftUI 绑定的同步判定（输入法安全） | 纯逻辑、可单测（BUG-005） |
| `App/AppState.swift` | 连接、页签、结果、数据库上下文、历史、服务缓存、任务 | 唯一 `@MainActor` 状态源 |
| `App/EditorCommandCenter.swift` | 工具栏 → 当前编辑器的一次性命令通道 | 单请求 + `id` 去重 |
| `App/Views/*` | 界面 | 只读 `AppState`、只发意图 |
| `Core/PrivilegeProbe.swift` | 权限探测三态解析 + 库名预校验（FR-META-11） | 纯逻辑、可单测 |

## 4. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 背景 / 理由 | 影响 |
|---|---|---|---|
| ADR-01 | 协议层与方言层分离（`DatabaseService` vs `SQLDialect`） | 目标是同一客户端支持 PostgreSQL 与 GBase 8a；SQL 方言差异集中在方言层 | 新增数据库类型只加实现，不动 UI（NFR-MAINT-02） |
| ADR-02 | 执行结果用 `AsyncThrowingStream<QueryEvent>` 暴露 | 需要同时表达「开始 / 结果集 / 影响行数 / 通知 / 结束」，并能逐行流入避免大内存峰值 | UI 与 CLI 共用同一抽象 |
| ADR-03 | 服务缓存按 `(connectionID, database)` 而非仅 `connectionID` | PostgreSQL 不支持跨库查询，切换目标库必须换连接 | 支持对象树跨库浏览（FR-META-10）与数据库下拉 |
| ADR-04 | 服务缓存 + 连接任务去重（`connectTasks`） | 同一 (连接, 库) 可能被对象树与查询同时命中，避免重复建连与竞态 | 连接复用、并发安全 |
| ADR-05 | DML 影响行数走「双路径」执行 | 流式 API 不暴露 command tag；无结果集的 DML 用 EventLoopFuture 版本读 `metadata.rows` | 仅 `INSERT/UPDATE/DELETE`（无 `RETURNING`）走该路径，其它保持流式（R-01） |
| ADR-06 | 服务端取消用「另开连接 + `pg_cancel_backend(pid)`」 | 同一连接发取消语句只会排队；CancelRequest 报文需 backend key，等价但更复杂 | 取消语句、连接保持可用（R-02 关闭） |
| ADR-07 | 对象树用扁平化行 + 自维护展开状态 | SwiftUI `List` + 嵌套 `DisclosureGroup` 在第 3 层起不可靠 | 任意层级可展开、可跨库（T-03） |
| ADR-08 | 编辑器命令通过 `EditorCommandCenter` 单通道传递 | 工具栏需要操作非 SwiftUI 管理的 `NSTextView` | 命令执行一次即失效（`id` 比对） |
| ADR-09 | 本地化：`LKey` 枚举 + 双语文案表 + 根视图 `.id(language)` 重建 | 需要切换后立即全量生效且可单测覆盖 | 新增文案必须同时补两种语言（单测强制） |
| ADR-10 | 查询历史只驻留内存 | DR-02 隐私优先：不落盘、不可被恢复 | 退出即清空；上限 50 条 |
| ADR-11 | 文件页签不绑定连接 | 打开 `.sql` 时没有「语义上的连接」，强制绑定会误导 | 未绑定页签可编辑，执行前提示选择连接（FR-EDIT-15） |
| ADR-12 | 页签编号由 `TabNumberGenerator` 单调生成 | 旧实现 `tabs.count + 1` 在关闭页签后会重复 | 关闭 / 重命名不影响编号（FR-EDIT-24） |
| ADR-13 | 保存查询与连接配置分文件存储，均不含密码 | 密码只在钥匙串；配置可读可迁移 | `connections.json` / `saved-queries.json` |
| ADR-14 | 构建走 SwiftPM（CLI + 脚本），Xcode 工程由 XcodeGen 生成 | 命令行环境（只读缓存）下 `xcodebuild` 解析依赖不稳定 | `Scripts/build-app.sh`、`verify-core.sh`、`test-local-query-path.sh` |
| ADR-15 | 沙箱 + ad-hoc 签名用于本地运行 | 需要 `network.client` 与用户选择文件读写 | 正式发布需 Developer ID + 公证（见 `Docs/发布方案.md`） |
| ADR-16 | 编辑器文本同步走 `EditorTextSync` 判定 + 文本编辑替换 + 延后着色 | 中文输入法组字期间整段替换 `textView.string` 会重置输入上下文，提交后光标跳到串首（BUG-005） | 组字期间不回写；仅真正外部改动才用 `textStorage.replaceCharacters` + `didChangeText` 替换；高亮延后到下一个 runloop |
| ADR-17 | 对象树右键菜单「按能力呈现」+ 刷新令牌 | 菜单里放必然失败的入口（如无权限账号的「新建数据库」）会误导用户；树刷新又需要由数据变化驱动 | `databaseCreationPrivilegeQuery()` 探测权限，三态（可/不可/未知）只有「可」才呈现；条件式 `contextMenu` 只在服务器节点挂载；建库后自增 `metadataRevision` 令牌驱动重载 |

## 5. 并发与生命周期

| 对象 | 隔离域 | 生命周期 |
|---|---|---|
| `AppState` | `@MainActor` | App 生命周期 |
| `PostgresService` / `MetadataService` | `actor` | 按 `(connectionID, database)` 缓存；连接参数变化或删除时 `invalidateService` |
| 执行任务 | 每个页签一个 `Task`（`executionTasks[tabID]`） | 执行开始创建；结束 / 取消后清理；页签关闭时结果不再回写 |
| 元数据加载 | 视图内 `Task` | 展开节点时触发；对象树自维护展开状态 |
| 流消费 | `AppState` 内 `for try await` | 中断时（页签关闭）停止更新，避免下标越界 |

取消语义：

1. 「停止」→ `executionTasks[tabID].cancel()`（本地立即停止消费）；
2. 同时 `service.cancel()` → 另开连接执行 `pg_cancel_backend(pid)`（服务端真正中断，释放资源）；
3. 任一步失败都不影响另一步（取消失败只影响资源释放速度）。

## 6. 错误处理与本地化

| 层 | 错误形态 | 处理 |
|---|---|---|
| Core | `AppError`（配置 / 连接 / 持久化 / 查询）与驱动错误（`PSQLError`） | 不吞错；必要时附上下文（表名、SQL 片段） |
| AppState | 统一经 `ErrorPresenter.message(for:)` 转成可读文案 | 状态栏「执行失败」+ 错误详情条 |
| UI | 空态 / 失败态 / 加载态三态明确 | 对象树、结果区均有对应视图与重试入口 |
| 文案 | 全部走 `LKey` | 单测校验两种语言齐全、无缺项 |

## 8. 已知边界（与设计相关）

| 边界 | 说明 | 关联 |
|---|---|---|
| 结果一次性载入内存 | 按 `maxRows` 截断但仍是全量读入 | R-03 |
| `WITH … UPDATE`、`COPY`、DDL 无影响行数 | 判定规则只覆盖 `INSERT/UPDATE/DELETE` | R-01 残留 |
| 无 `application_name` / `statement_timeout` 下发 | `QueryOptions.statementTimeout` 已建模未使用 | 见 §10.4 |
| 编辑器与输入法 | 已按 BUG-005 处理组字 / 提交时序；仍需在主流输入法（拼音 / 五笔 / 日文）下人工回归 | 见 `Docs/测试用例.md` TC-64 |
| GBase 驱动未实现 | 方言层就绪，驱动层待实例 | T-15 / `Docs/GBase-技术验证.md` |
| macOS 14 / Intel 未实测 | 仅验证 macOS 27 + arm64 | NFR-COMP-01 / 02 |
