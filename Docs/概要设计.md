> **为什么要有这份"双平台"改版**：产品要在 macOS 与 Linux 上做到**功能一致**（平台与编程语言不同）。
> 原版概要设计是一份 **macOS/Swift 实现说明**（模块清单按文件、ADR 按 Swift 类型），
> 直接照它做 Linux 版会把实现细节当成需求。改版把内容分成两层：
> **契约层（跨平台不变）**与**实现层（按平台可替换）**，并明确"哪些允许不同"（见 §4）。

## 1. 设计目标与约束

| 目标 / 约束 | 说明 | 跨平台要求 |
|---|---|---|
| 协议层与方言层严格分离 | 驱动只做协议传输；所有 SQL 文本由方言层生成 | **契约**，两平台同构（NFR-MAINT-02） |
| 领域逻辑可单测 | 领域层不得依赖 GUI 框架；一条命令跑完全部单测 | **契约**（NFR-MAINT-01）；Linux 侧同样要求"GUI 框架不得进入领域层" |
| 事件流驱动界面 | 执行过程以**事件流**暴露，界面按事件更新，不阻塞 UI 线程 | **契约**：事件种类、顺序与不变量见 §3.3 |
| 安全与隐私 | 凭据只进系统凭据库；查询历史不落盘；目录访问走用户授权 | **行为契约**；具体机制按平台替换（§4 P-02 / P-03） |
| 双平台行为等价 | 同一需求在两个平台上**行为一致**（含错误分类、空态、确认弹窗、快捷键语义） | **契约**：凡"允许不同"的必须在 §4 登记，否则视为必须一致 |
| 可验证 | 每个关键行为都有单测 / 链路脚本 / 手工验收之一 | **契约**：两平台都要有等价的三道闸门（见 §8.3） |

## 2. 分层架构（语言无关）

```
┌──────────────────────────────────────────────────────────────────┐
│ 表示层（平台 GUI：窗口 / 菜单 / 列表 / 编辑器 / 结果表 / 终端视图）  │
│  只读应用状态、只发用户意图；不含业务规则                          │
└───────────────▲───────────────────────────┬──────────────────────┘
                │ 状态通知                   │ 用户命令
┌───────────────┴───────────────────────────▼──────────────────────┐
│ 应用状态层（连接 / 页签 / 结果 / 上下文 / 历史 / 服务缓存 / 任务）  │
│  唯一状态源；UI 线程亲和；一个页签一个执行任务                      │
└───────────────▲───────────────────────────┬──────────────────────┘
                │ 事件流 / 元数据             │ SQL 文本
┌───────────────┴───────────┐  ┌────────────▼──────────────────────┐
│ 协议层（驱动契约）          │  │ 方言层（SQLDialect 契约）          │
│  connect/execute/cancel/事务│  │  库列表 / 引用 / 分页 / 事务 / 类型名│
└───────────────▲───────────┘  └────────────┬──────────────────────┘
                │                            │
┌───────────────┴────────────────────────────▼──────────────────────┐
│ 服务层：元数据枚举（对象树）、结果格式化、导出、语句拆分              │
└───────────────▲───────────────────────────────────────────────────┘
                │
┌───────────────┴───────────────────────────────────────────────────┐
│ 领域工具层：词法分析 / 静态检查 / 格式化 / 补全 / 设计令牌 /         │
│ 本地化 / 智能体治理（闸门 / 护栏 / 审批 / 审计 / 配额）/ 归档 / 记忆  │
│  —— **纯逻辑，无 GUI、无网络副作用、可单测**                        │
└───────────────────────────────────────────────────────────────────┘
```

**平台适配点只有三处**（其余全部应当是共享契约或纯逻辑）：
1. **GUI 框架**：macOS = SwiftUI + AppKit 桥接；Linux = 由 Linux 侧选定（GTK / Qt / 其它）。
2. **系统能力**：凭据库、目录授权、剪贴板、字体与输入法、进程与 PTY、外部程序调用。
3. **打包与分发**：macOS = `.app` + 签名 / 公证；Linux = 发行包（deb / rpm / AppImage…）。

> **纪律**：任何"新功能"若必须落在适配层，说明它要么是系统能力（登记到 §4），
> 要么是设计漏了（应当回到领域层实现）。

## 3. 【契约】平台适配层契约（跨平台不变量）

本节是**两个平台必须一致**的部分。Linux 侧照此实现即可，不必读 Swift 代码；
macOS 侧现有的 Swift 类型是它的一个实现（对应关系见 §8.1）。

### 3.1 连接配置（ConnectionConfig）

| 字段 | 语义 | 要求 |
|---|---|---|
| `id` | 稳定标识（UUID） | 配置文件里的主键；改名不改 id |
| `name` | 展示名 | 允许重名；UI 需消歧 |
| `dbType` | 数据库类型枚举 | 至少 `postgresql` / `gbase8a`（`mysql` 见 FR-DRV-09） |
| `host` / `port` / `username` / `database` | 连接参数 | 端口按类型给默认值（PG 5432 / GBase 5258 / MySQL 3306） |
| `sslMode` | SSL 模式枚举 | PG 六档（disable / allow / prefer / require / verify-ca / verify-full）；GBase 默认 disable |
| `timeout` | 连接超时（秒） | 默认 5，可配置 1–60 |
| `schemaVersion` | 配置格式版本 | 为将来迁移预留（FR-CONN-10） |

**不变量**：
- **配置文件绝不包含密码**（NFR-SEC-02）；凭据按平台存系统凭据库（§4 P-02）。
- 配置写入必须**原子**（不产生半截文件），损坏时给可读错误、不静默清空（NFR-REL-03/04）。

### 3.2 驱动契约（DatabaseService）

| 方法 | 语义 |
|---|---|
| `connect() → ServerInfo` | 建立连接；`ServerInfo` 含版本、当前库、当前用户 |
| `disconnect()` | 关闭连接；**必须可重入** |
| `execute(sql, options) → 事件流` | 流式暴露执行过程（§3.3） |
| `cancel()` | 请求**服务端**中断当前语句（不是只停本地消费） |
| `beginTransaction()` / `commit()` / `rollback()` | 事务控制 |

**不变量（每条都可作为跨平台验收点）**：
1. **取消必须同时作用于两处**：① 中断本地消费；② 请求服务端中断。
   只做①是**缺陷**（评审 R-29：剩余语句会照旧执行）。
2. **取消必须可达**：拿不到服务端会话标识时要给出可读状态或退化为"断开连接"，
   **不得静默无操作**（评审 R-30）。
3. **一条语句的影响行数只报告一次**（评审 R-32：不得既随结果集又单独报告）。
4. **截断必须可见**：命中行数上限时结果需带 `isTruncated` 标记（评审 R-31）。
5. 每条语句的执行**恰好**产生一组事件，顺序见 §3.3；异常路径也必须收尾。
6. 驱动不得吞错：错误要带可读原因与错误码（§6）。

### 3.3 执行事件模型（QueryEvent）

```
.started(index)                  每条语句开始（index 从 0 递增）
.resultSet(QueryResult)          有结果集时（列元数据 + 行 + 可选影响行数）
.affectedRows(count)             DML 影响行数（与 .resultSet 二选一，见 §3.2 不变量 3）
.notice(message)                 服务端通知 / 警告（可 0..n 次）
.finished(QuerySummary)          全部结束（语句数 + 总耗时），恰好一次
```

**不变量**：`.started(i)` 之后才会出现该语句的事件；`.finished` 恰好一次且最后；
消费方被取消时，生产方**也必须停止**（§3.2 不变量 1）。

**结局必须可区分**（跨平台统一）：成功 / 失败（带可读原因）/ **被取消** / **被截断**。
"被取消"不得记成"成功"（评审 R-29）。

### 3.4 结果模型（QueryResult / ColumnMeta）

| 形状 | 字段 | 要求 |
|---|---|---|
| `ColumnMeta` | `name` / `typeName` / 可空标记 | `typeName` 用**数据库方言的原名**（不翻译） |
| `QueryResult` | `columns` / `rows: [[String?]]` / `affectedRows?` / `executionTime` / `isTruncated` | `rows` 是**已格式化的展示字符串**，`null` 表示 SQL NULL |
| `QueryOptions` | `maxRows?` / `statementTimeout?` / `fetchSize` | **默认值必须给上限**（评审 R-31）；超时未实现视为缺陷 |

**不变量**：
- **单元格格式化在领域层完成**（不是 UI 层）：NULL → `null`；二进制 → 可读占位
  （如 `<binary N bytes>`）；日期 / 时间 / 数值的一致表示。
  这条保证**两个平台看到的同一份数据长得一样**。
- 数值列的可排序性：能解析为数字的列按数值排序（FR-RES-08）。

### 3.5 方言契约（SQLDialect）

必须覆盖：库列表、标识符引用、分页语法、事务语句、类型名映射、表结构查询、
执行计划、会话列表 / 取消 / 终止、权限探测（三态：可 / 不可 / 未知）。

**不变量**：**任何 SQL 文本都不得出现在驱动层或界面层**；
新增数据库类型只加一份方言实现（NFR-MAINT-02）。

### 3.6 元数据与对象树

| 形状 | 字段 | 要求 |
|---|---|---|
| `DatabaseObject` | `id` / `kind` / `name` / `schema?` / `detail?` / `isExpandable` | `kind` 至少含 server / database / schema / table / view / column |
| 层级 | PG：服务器 → 库 → schema → 表 / 视图 → 列；GBase 8a：服务器 → 库 → 表 / 视图 → 列（**无 schema 层**） | 层级差异由方言声明，两平台一致 |

**不变量**：**单层懒加载**（展开才读下一层）；展开状态由界面自维护；
刷新由"元数据版本号"驱动（避免全树重建导致闪烁）。

### 3.7 终端屏幕模型（内嵌终端）

**这份契约是"终端看起来一样"的关键**，与 GUI 框架无关：

| 能力 | 要求 |
|---|---|
| VT 子集 | 光标移动 / 擦除 / 插入删除行与字符 / 滚动区域 / SGR（16 色 + 256 色 + 真彩）/ DECSC·DECRC / 延迟换行 |
| 宽字符 | 中日韩占 2 格，右半格标记为"续格"；**绘制必须按格定位**（不得靠字体前进宽度累加） |
| 回滚缓冲 | 上限与行为固定（当前 2000 行）；提供"视口偏移"读取 |
| 备用屏 | `?1049` / `?47`：保存并恢复主屏与光标；**备用屏上滚屏不得灌入回滚区** |
| 输入 | 控制键 / 方向键 / 功能键 → 固定字节序列；**可打印输入必须走输入法通道**（IME 组字） |
| 选择与复制 | 选区按格吸附（宽字符整字选中）、行尾裁剪、反向拖动一致 |
| 窗口尺寸 | 尺寸变化 → 通知子进程（POSIX: `TIOCSWINSZ` → SIGWINCH） |

### 3.8 工作区（用户自选目录）

**不变量**：
1. 目录必须**由用户选择**产生（不得硬编码路径）；授权凭据可持久化（机制按平台，§4 P-03）。
2. 文件树**单层懒加载**；忽略名单（构建产物 / 依赖 / 版本库元数据）；
   **符号链接只显示不跟随**。
3. **路径包含判定按路径分量比较**，不得用字符串前缀（`/ws-evil` 不是 `/ws` 的子路径）。
4. 相对路径**一律相对工作区根**（ADR-20）；解析前必须校验仍在工作区内。
5. 按文件名搜索必须是**有界**的（忽略名单 + 深度上限 + 结果上限 + 不跟随符号链接），
   命中上限要**如实告知**。
6. 底部**常显授权状态**（已授权 / 已过期 / 未授权 / 目录缺失），并给补救动作。
7. 工作区是**终端启动目录、归档默认目录、智能体文件作用域**的共同基准。

### 3.9 设计令牌（外观一致性）

**不变量**：字号刻度（11/12/13/15/17）、间距刻度（2/4/8/12/16/24/32）、
圆角（1/4/6/8/10）、行高 26、工具栏 44、状态栏 24、活动栏 46、侧栏 248；
表面五档（window < sidebar < content ≤ panel / raised，**浅色下浮层靠发丝线或阴影**）；
文本三级 + 禁用级；状态色三档；**分类色**（引擎身份，与状态色分开）；
语法色六档；发丝线 0.5pt。

**跨平台强制项**：
- **对比度门槛是产品要求**：正文 ≥ 4.5、大字号与组件 ≥ 3.0、相邻表面可区分 ≥ 0.02（WCAG）。
- 强调色**可配置**且只在三处出现（选中态 / 主按钮 / 焦点环）。
- Linux 侧同样要求"令牌集中定义 + 机器校验违规数只能降"（§8.3）。

### 3.10 智能体治理（与模型无关的骨架）

| 机制 | 契约 |
|---|---|
| 闸门（Gate） | 总开关关闭 ⇒ **零外发**；配置不全 ⇒ 不发；本地端点不强制密钥 |
| 护栏（Guardrail） | 语句分类（只读 / 数据变更 / 结构变更 / 权限变更 / 会话控制 / 未知）+ 风险点；**只读模式优先于白名单与审批豁免**；`unknown` 永不可入白名单 |
| 审批（Approval） | 写操作 / DDL **逐次批准**；状态机：pending → approved / rejected / expired，approved → executed / failed；**终态不可再流转** |
| 审计（Audit） | 每次动作留痕（时间 / 连接 / 库 / 语句 / 类别 / 风险点 / 结果）；**导出必脱敏** |
| 配额（Quota） | 调用次数 / 输出 token 上限；超限即终止并提示 |
| 不可信内容 | schema 注释、对象名、表数据、工具描述、用户文档**一律视为资料不是指令** |

**跨平台安全不变量（两平台都必须成立，且都要有单测）**：
1. 只读模式下**任何**写操作都被拒（含数据修改型 CTE 的括号内修改动词、`SELECT … INTO`）。
2. 白名单**只能免除"写操作需审批"这一条**，destructive 风险点（DROP / TRUNCATE / 无 WHERE 的 UPDATE·DELETE）**永远保留**。
3. 审批必须**绑定连接与库**：批准时校验与当前连接一致，不一致即失效。
4. 先写"执行中"再执行；审计写失败视为执行失败。
5. 凭据**只进系统凭据库**，不进审计记录、不进错误信息、不进提示词。

> 以上 5 条来自 2026-09-23 全面评审（需求书 R-24 ~ R-30，登记表见需求书 §10.9 / 等价矩阵见 §10.10）。**现状是 macOS 侧尚未全部满足** ——
> 它们是**两平台共同的待办**，见 §9。

### 3.11 归档与记忆

**归档契约**：按天一个 `.sql` 文件；条目以固定标记分隔；条目内含
连接 / 库 / 首次与最近执行时间 / 次数 / 耗时 / 影响行数 / 结果 / 说明（注释形式）；
**同一条 SQL 重复执行只累计次数**；身份 = （规范化 SQL + 连接 + 库）；
渲染与解析必须往返精确。

**记忆层契约**（FR-AI-13 ~ 15）：**事实源是归档文件**，索引是**纯派生缓存、可重建**；
按连接 / 环境隔离；两级指纹（结构骨架用于聚类、原文用于计数）不混用；
生命周期按类型分；用户可检视 / 可删除 / 可解释。

### 3.12 内嵌浏览器（FR-EDIT-34）

**视图契约**：浏览器是**编辑器区**里的一类页签（与 SQL 页签同级），不是下方面板的一个页签。
因此它必须能与 SQL 页签并排、切换、关闭，并随会话恢复（URL / 标题 / 前进后退历史）。

**行为契约（与实现引擎无关，P-14）**：

| 约束 | 内容 | 为什么 |
|---|---|---|
| 默认不外发 | 新建页签为空白页 + 地址栏，**不加载任何远程内容**；一切导航由用户显式发起 | 与「默认零外发」的既有纪律一致；页签恢复时也不自动重放导航 |
| 出网必留痕 | 每条出网请求（文档 / 子资源 / 下载）写进**统一外发日志**（§3.13） | 浏览器是第一个通用出网入口，不可观测就等于放弃这条承诺 |
| 存储隔离 | **独立** Cookie / 缓存 / 存储目录，不与连接凭据或客户端数据混放 | 网页内容不可信，不能让它碰到数据库凭据 |
| 文件访问 | 下载与本地文件访问沿用**授权目录**模型（§3.8），不静默写盘 | 与 FR-AI-08 同一套授权语义 |
| 不注入能力 | **不向页面注入客户端脚本桥**，网页无法调用数据库能力 | 防"网页 → 本地能力"的越权通道 |
| 引擎可换 | 渲染引擎、Cookie 存储位置、权限提示方式按平台实现 | 见 §4 P-14 |

**实现状态（2026-09-23）**：**契约层已完成** —— `Core/BrowserPage.swift`（`BrowserPage` / `BrowserNavigationPolicy` / `BrowserSession`）+ `Tests/BrowserContractTests.swift`（13 项）；平台引擎适配（macOS 用 `WKWebView`）与页签集成待做，见 `Docs/design/浏览器页签-设计说明.md`。**边界**：`WKWebView` 不暴露单个子资源请求，日志按导航级记录。

**平台验收点（两侧都要有）**：默认页签不出网；显式导航产生日志条目且条数与请求类别对应；
关闭浏览器后日志不再增长；删除浏览器数据存储不影响连接与凭据。

### 3.13 统一外发日志（NFR-SEC-08）

**契约**：**所有**离开本机的网络请求写进同一份日志。范围包括：智能体模型调用、内嵌浏览器
导航与子资源、外部程序调用（`pg_dump` / `ssh` 等）、更新检查。

**记录字段（两侧一致）**：时间、目标（主机 / URL 或程序名）、**触发来源**（哪个功能、哪个页签或会话）、
结果（成功 / 失败 / 被闸门拒绝）。可查看、可导出（JSON / CSV，与既有智能体审计日志同格式）、可清空。

**不变量**：

1. **零外发可验证**：关闭智能体、未打开浏览器、未调用外部程序时，日志为空。
2. **不记敏感内容**：不含密钥、不含结果集行数据（与 NFR-SEC-05 同纪律）。
3. **一个写入点**：脱敏与字段形状只在一处实现；各功能不得自行写日志或另建日志文件。
4. **拒绝也留痕**：被闸门拦下的请求同样记一条（"想发但没发出去"和"没想发"是两件事）。

**实现（macOS 侧，2026-09-23）**：`Core/EgressLog.swift`（模型 + actor 存储 + 净化 + 导出）、`EgressRecordingTransport`（装饰 `HTTPTransport`，所有 HTTP 出网自动留痕）、`App/Views/EgressLogSheet.swift`（⇧⌘E 面板）；拒绝路径在 `AgentSQLGenerator` / `DataTaskSpecGenerator` 的 `AgentGate.decide` 判定处记 `denied`。**其余平台按同一契约实现**：记录字段与四条不变量是契约，存储位置与查看入口属实现。

**与既有实现的衔接**：智能体审计日志（`AgentAuditLog`）聚合的是**动作与审批**，
外发日志聚合的是**出网请求**；两者字段有重叠但不合并 —— 一次动作可能产生零次或多次出网请求。

| ADR-12 | 页签编号单调生成 | 关闭 / 重命名不影响编号 |
| ADR-13 | 保存查询与连接配置分文件存储，均不含密码 | 可读可迁移 |
| ADR-18 | 设计令牌层 + **棘轮式防回潮校验** | 外观一致性可机器校验（§8.3） |
| ADR-19 | 目录授权凭据**两种模式兼容** | 有能力作用域就作用域，没有就普通凭据；对调用方透明 |

## 6. 并发与生命周期（概念级）

| 对象 | 要求 |
|---|---|
| 应用状态 | **单一线程亲和**（UI 线程持有）；跨线程只传值类型 |
| 驱动连接 | 连接对象**串行化**访问（同一连接不并发执行两条语句） |
| 执行任务 | 每个页签一个任务；页签关闭后结果不再回写（不得下标越界） |
| 元数据加载 | 展开节点触发；同一节点并发展开需去重 |
| 连接去重 | 同一 `(连接, 库)` 的并发建连请求共享同一结果（成功与失败都要清理登记） |
| 大结果解码 | **不得在 UI 线程**（否则界面卡死） |
| 归档写入 | **串行化**（两次执行几乎同时结束时"读-改-写"会互相覆盖） |

**取消语义（契约）**：① 中断本地消费；② 请求服务端中断；③ 两者互不影响；
④ 取消后界面必须显示"已取消"、历史 / 归档必须记"未成功"。
