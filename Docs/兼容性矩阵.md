### 2.1 未实测版本的补测步骤

1. 准备任意一个 PostgreSQL 12–15 / 17 实例（本机安装、局域网实例、或可用容器）。
2. 确认账号对目标库有建表 / 建 schema 权限；跨库用例另需 `CREATEDB`（无权限时加 `--skip-cross-db`）。
3. 执行：

   ```bash
   PGHOST=<host> PGPORT=<port> PGUSER=<user> PGPASSWORD=<pwd> \
     PGDATABASE=postgres PGSSLMODE=disable \
     ./Scripts/test-postgres-version-matrix.sh
   ```

4. 脚本会自动清理测试表 / 测试库，并在结尾打印一行 Markdown；把它粘贴到 §2。
5. 若某用例失败：在 §3 对应行把结论改为 ❌，并在 `Docs/需求规范书.md` 的 R-01 / R-02 / NFR-COMP-03 中记录差异（含错误码与错误原文）。

## 3. 版本敏感点复核

> 说明：本表是**静态复核**（客户端用到了哪些服务端能力、这些能力从哪个版本开始存在），
> 「引入版本」列来自 PostgreSQL 官方文档（未逐版本实跑）；实测状态列才是本工程的真实证据。

| 客户端能力 | 客户端用法 | 服务端特性 | 引入版本（官方文档） | 12–18 是否可用 | 缺失时的降级行为 |
|---|---|---|---|---|---|
| 连接与版本探测 | `SHOW server_version` | GUC 查询 | 7.0 起 | ✅ | 无法连接时给出可读错误 |
| 当前库 / 当前用户 | `SELECT current_database()` / `SELECT current_user` | 系统函数 | 7.4 / 6.x 起 | ✅ | — |
| 数据库列表（按权限过滤） | `SELECT datname FROM pg_database WHERE has_database_privilege(current_user, datname, 'CONNECT')` | `pg_database` + `has_database_privilege()` | `pg_database` 7.1 起；`has_database_privilege` 8.1 起 | ✅（两者都远早于 12） | 若函数不存在：连接成功但数据库下拉为空 —— 目前无此降级分支，需按错误提示排查 |
| schema / 表 / 视图 / 列枚举 | `information_schema.schemata` / `.tables` / `.columns` | `information_schema` 视图 | 7.4 起 | ✅ | 单库失败被隔离（跨库浏览时其它库仍可展开，FR-META-10） |
| 后端 PID（取消用） | `SELECT pg_backend_pid()` | 系统函数 | 8.1 起 | ✅ | 取不到时退化为「只取消本地等待」（`PostgresService.cancel()` 直接返回） |
| 服务端取消 | 另开连接执行 `SELECT pg_cancel_backend($pid)` | 系统函数 | 8.1 起 | ✅ | 权限不足时日志告警，本地 Task 取消仍生效 |
| 语句拆分（含美元引号） | 客户端按 `;` 拆分并跳过 `$$ … $$` | dollar-quoted string（8.0 起）/ 标准字符串 | 8.0 起 | ✅ | 老版本不支持美元的语法本身不会出现在客户端 SQL 中 |
| DML 影响行数 | 读 command tag（`INSERT 0 3` / `UPDATE 5` / `DELETE 1`） | CommandComplete 报文 | 协议 v3（7.4 起） | ✅ | 无影响行数时仅不显示数字 |
| `RETURNING` 结果集 | 流式读取结果（列名来自 RowDescription） | `RETURNING` | 8.2 起 | ✅ | 不支持时语句本身报错（用户 SQL 层问题） |
| 事务控制 | `BEGIN` / `COMMIT` / `ROLLBACK` | 协议 + SQL | 7.x 起 | ✅ | — |
| 认证方式 | 明文 / MD5 / SCRAM-SHA-256（PostgresNIO 自动协商） | `pg_hba.conf` 认证方法 | SCRAM 10 起；MD5 12 前默认 | ✅（12+ 默认 SCRAM 或 MD5 均可） | 认证失败返回 `PSQLError`，界面给出可读详情 |
| 传输加密 | `SSLMode`：disable / prefer / require（不做证书链校验） | TLS 1.2+ | TLS 1.2 自 12 起默认启用 | ✅ | `require` 在服务端未开 TLS 时直接失败（预期行为） |
| 超时与连接中断 | `timeout` → 连接超时；TCP 断开 → 可读错误 | — | — | ✅ | 连接错误会给出「Connect timeout」等原始信息 |
| 权限枚举（表 / 列） | 未使用 `has_*_privilege` 过滤表清单 | —— | —— | —— | 表清单不过滤权限（用户可见 schema 下的全部对象） |
| 建库权限探测（FR-META-11） | `SELECT (rolsuper OR rolcreatedb) FROM pg_roles WHERE rolname = current_user` | `pg_roles.rolsuper` / `rolcreatedb` | 8.1 起（`rolcreatedb` 随 `pg_roles` 引入） | ✅（远早于 12） | 探测失败或返回未知时**不呈现**「新建数据库」入口 |

### 3.1 已知的版本无关边界（与 PG 版本无关，属于驱动 / 协议限制）

| 边界 | 说明 | 影响 |
|---|---|---|
| `WITH … UPDATE/INSERT/DELETE` 不显示影响行数 | 客户端只在语句首关键字为 `INSERT/UPDATE/DELETE`（且无 `RETURNING`）时读取 command tag | 仅缺数字，不影响执行 |
| `COPY`、DDL 不显示影响行数 | PostgreSQL 对 DDL 的 command tag 本身不携带行数；`COPY` 未纳入判定 | 同上 |
| 结果一次性载入内存 | 当前实现（R-03）按 `maxRows` 截断但仍是全量读入 | 超大结果集内存占用高，见 R-03 |
| 无 `application_name` / `statement_timeout` 下发 | `QueryOptions.statementTimeout` 已建模但未下发到服务端 | 超时依赖客户端取消 |
