# 待人工验收清单（今晚集中点验用）

> **为什么有这份文档**：现在 48 条 🟡 里，绝大多数**代码已经写完、脚本也验过**，缺的只是"人在界面上点一下 / 看一眼"。
> 这些条目不能由我改状态（本项目的纪律：**状态只在验证之后改**），所以把"要点什么、看什么、什么算通过"集中成一张表。
> 每条都写清三件事：**怎么点** / **什么算过** / **机器已经验过什么**（脚本或单测，可复跑）。
> 点完把结论回写到 `Docs/需求规范书.md` 对应行的「状态 / 证据」格（🟡 → ✅，或记下不合格的具体现象）。

## 0. 用法（3 步）

1. **先跑脚本**（机器能判的部分，别用人眼重复）：`bash Scripts/verify-all.sh`；涉及具体能力的脚本见每行「机器已验」列。
2. **按表点验**：一行的步骤做完就写结论。判据写在「什么算过」里 —— **模糊的"看起来没问题"不算过**。
3. **回写状态**：过了就把该行状态改成 ✅ 并补一句日期与观察结论；没过就把现象写进 §9 风险表或直接告诉我，我修。

需要更长的分步清单时，本表会指向 `Docs/手工验收运行手册.md` 里的 **清单 A ~ I**（那份是本地文件，不随仓库发布）。

## 10.11 三档呈现与许可证（FR-LIC-02 / FR-NOTE-24 / 25，2026-09-25 界面已接线）

**怎么造出三档来验**（本机就能做，不用账号、不用联网）。许可证文件放这儿：
`~/Library/Application Support/DoyahStudio/license.doyahlicense`；没有这个文件就是 **Standard**。

```bash
# 一次性：生成一把发行密钥（私钥留本机，别提交）—— 本机已有一把：~/.doyah-license/issuer.key
swift run doyah-license-tool keygen --out ~/.doyah-license/issuer.key
# 发一张 Ultra（三块全给）
swift run doyah-license-tool issue --key ~/.doyah-license/issuer.key \
  --to alex --edition ultra --max-devices 5 \
  --out ~/Library/Application\ Support/DoyahStudio/license.doyahlicense
# 发一张 Pro（只要工作区 + 数据库），standard 同理换成 --edition standard
swift run doyah-license-tool issue --key ~/.doyah-license/issuer.key \
  --to alex --edition pro \
  --out ~/Library/Application\ Support/DoyahStudio/license.doyahlicense
# 换完**不用重启**：菜单「版本与许可证…」→「重新读取许可证」
```

**两条排障用的小路**（验收时很省事）：
· `~/Library/Application Support/DoyahStudio/startup.log` 每次启动会记一行
  `许可证：ultra / 活动栏 [workspace,database,notes] / 许可证有效` —— **哪一档、栏上有哪几项、为什么**，
  一眼就能看（用户报「工作区不见了」时先看它）；
· `DOYAH_LICENSE_PATH=<某文件>` 可以把"从哪儿读许可证"指到别处，**不动上面那份真文件**
  （同 `DOYAH_SSH_BINARY` / `DOYAH_LICENSE_PUBLIC_KEY` 的套路）。注意它只在**直接跑二进制**或 CLI 时生效；
  用 `open dist/DoyahStudio.app` 启动时环境变量不会被带进去 —— 那条路请直接换文件。

> **本机实测（2026-09-25，四种状态各启动一次，读的就是上面那行 startup.log）**：
> `pro → 活动栏 [workspace,database] / 许可证有效`、`ultra → [workspace,database,notes] / 许可证有效`、
> `standard（真许可证）→ [notes] / 许可证有效`、`无许可证 → [notes] / 还没有放许可证（当前呈现 Standard）`。
