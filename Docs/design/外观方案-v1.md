## 1. 为什么当前界面"简陋"（量出来的，不是感觉）

| 项 | 现状 | 后果 |
|---|---|---|
| 主题 / 令牌层 | **不存在** | 每个视图各自为政，同一语义在不同面板里不是同一个值 |
| 显式字号 | 全 App 只有 **3 个**（14 / 15 / 9），其余靠默认 `.body` | 没有排版级差：标题、正文、表头、辅助信息长得一样 |
| 材质 / 毛玻璃 | **0 处** | 工具栏与侧栏是纯色平铺，没有"浮在窗口上"的层次 |
| `Divider()` | **46 处** | 分隔靠系统实线，又多又重；精致感来自**更少、更淡的发丝线** |
| padding | `2` 出现 **139 次**，另混着 1 / 3 / 6 / 10 / 12 / 20 / 150 | 没有刻度 → 对齐"差一点点"，这是"看着不精致"的第一来源 |
| 颜色 | 语义色 + 零散 `Color.orange/.red/.blue`、`NSColor.system*`，**无调色板** | 同一种"警告橙"在不同面板里不是同一个橙 |
| 主窗口 | 就是一个 `NavigationSplitView`，无自定义 toolbar / 背景 | 层次全靠系统默认 |
| 结果网格 / 终端 | 自绘 AppKit | 完全可控，也完全没有系统加成 |

**结论：不是"macOS 风格不对"，是"没有设计层"。** 精致感的真正来源是一致性、层次、克制的细节。

## 2. 令牌（样张即按这套画的，将来落到 `Core/DesignTokens.swift`）

### 2.1 表面层次（不变式：**内容区明度最高**，chrome 比它暗）

| 令牌 | 深色专业 | 浅色原生 | 用在哪 |
|---|---|---|---|
| `window` | `#141619` | `#E8E8EC` | 窗口底（chrome 铺满时通常看不到） |
| `sidebar` | `#17191E` | `#EDEDF2` | 侧栏、标题栏、状态栏、页签条底色 |
| `content` | `#1F2229` | `#FFFFFF` | 编辑器、结果网格 —— **最亮的一面** |
| `panel` | `#262A31` | `#F6F6F9` | 下方面板、表头 |
| `raised` | `#2F343C` | `#FFFFFF` | 分段控件选中块、页签选中块、输入框 |
| `hairline` | 白 8% | 黑 9% | **唯一的**分隔手段（0.5pt） |

> 第一版深色只差 3/255，自检取样读回来三个面是同一个 `#21242C` —— 等于没有层次，已改为每级 ≥ 8/255。

| `danger` | `#E5534B` | `#D03A32` | `failed`、错误角标 |

### 2.3 排版级差

| 用途 | 规格 |
|---|---|
| 窗口标题 | 17 / semibold |
| 区块标题 | 15 / semibold |
| 正文 / 表格内容 | 13 / regular |
| 数据（数值列） | 12 / **monospacedDigit**（数字必须等宽对齐） |
| 代码 / 终端 | 12 / SF Mono |
| 辅助（表头、状态栏、行号） | 11 / medium |

### 2.4 度量

间距刻度 **4 / 8**（另有 2 用于紧贴场景）；圆角 **4 / 6 / 8 / 10**；发丝线 **0.5pt**；
行高 **26**；侧栏行高 **26**；页签高 **30**；工具栏 **44**；状态栏 **24**；侧栏宽 **248**。

### 2.5 语法着色（专业感最容易露怯的地方）

| 元素 | 深色 | 浅色 |
|---|---|---|
| 关键字 | `#9BA8FF` | `#8B33C4` |
| 标识符 | `#E7E9EE` | `#1D1D1F` |
| 字符串 | `#9ED37A` | `#1E7A3C` |

| 函数 | `#62C6C0` | `#0B6E99` |

## 3. 强调色的三个候选（**待你定**）

| | 名称 | 色值 | 来历 / 取舍 |
|---|---|---|---|
| A | **鲸鱼蓝** | `#4E6FFF` | 取自 `dsh-tui` 鲸鱼调色板 `B[78,111,255]`，与 App 图标（法斗 / 深蓝）同系 —— **品牌最自洽** |
| B | **深海青** | `#17A2A2` | 与红 / 橙告警区分度最大，数据表场景更冷静 |
| C | **鲸心品红** | `#CC3399` | 取自同一套调色板的心形色 `H[204,51,153]`，辨识度最高 |

三个候选在样张里都是**真实选中态**（选中行 = 14% 淡填充 + 左侧 3pt 强调条；主按钮 = 实心强调色；
焦点输入框 = 1.5pt 强调色描边），不是一块色卡。强调色**只在三处出现**：选中态、主按钮、焦点环 —— 这是"克制"的具体含义。

## 4. 样张自检（41 项全过）

渲染脚本不只看图，还会**取样核对**（空白图也是合法 PNG）：

1. 不变式「内容区是明度最高的表面」（深浅两套都成立）；
2. 表头 / 侧栏必须与内容可区分；
3. 强调色**分类**：按钮处取样必须最接近本次使用的候选；
4. 三个候选彼此必须可区分（距离 > 0.15）；
5. 文本与图标真的画上去了（编辑区 / 网格 / 侧栏 / 终端四块的非背景像素占比）。

**自检当场抓出并修掉了两处我自己设计里的缺陷**（深色层次只有 3/255、浅色侧栏与内容明度只差 0.009），
另外还发现「逐字节比对」这个判据本身是错的：位图是 deviceRGB，写进去的 sRGB 会被显示器 profile 转换一次
（`#16181D` 读回 `#21242C`），因此判据改为**结构关系 + 分类**。

## 5. 落地计划（确认后开工）

1. **令牌层**：`Core/DesignTokens.swift`（纯数据、可单测），零功能改动；
2. **防回潮**：`Scripts/check-design-tokens.py` —— App/ 里再出现裸 `Color.orange`、非刻度的 padding / 字号即报错；令牌加对比度单测（WCAG AA）；
3. **逐屏替换**，按你的使用强度排序：**结果网格 → 编辑器 → 对象树 → 页签 / 工具栏 / 状态栏 → 各功能面板**（数据任务、智能体、表设计等）。

## 6. 本方案尚未覆盖

对话框 / 表单（连接表单、表设计、数据任务面板）、智能体各面板、空状态与错误态、深浅色自动切换的细节、
以及"材质"的正式做法（样张里用色块近似毛玻璃，真机需要 `NSVisualEffectView` / `.background(.regularMaterial)` 叠加验证）。
