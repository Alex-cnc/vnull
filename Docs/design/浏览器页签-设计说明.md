| 文件 | 内容 |

**为什么先做契约层**：`WKWebView` 的代理里写策略 = 把安全规则焊进平台代码，换引擎就各写一份。
放进 Core 之后，两个平台共用同一套规则，而且**不需要真的开一个 WebView 就能测**。

## 2. 引擎适配（`Platform/macOS/WebKitBrowserEngine.swift`）· 已完成

实现 `BrowserEngine`（已在 Core 声明）：

```
WKWebView + WKNavigationDelegate
  decidePolicyFor navigationAction
    ├─ 取 action.request.url 与 navigationType 判定 isUserInitiated
    │   （.linkActivated / .formSubmitted / .backForward 视为用户发起；
    │     地址栏导航由 App 直接调 load(_:) —— 那条路径本身就是用户发起）
    ├─ BrowserNavigationPolicy.decide(...)
    ├─ await BrowserSession.record(...)   ← 拦截与放行都留痕
    └─ decisionHandler 对应 .allow / .cancel
  didStartProvisionalNavigation / didFinish / didFail → 更新 BrowserPage 并回调
```

**必须注意的三点**：
1. `isUserInitiated` 的判定错了，就等于把"默认不加载远程内容"这条保证弄丢 —— 这是本页签最重要的安全属性，
   要有针对性用例（哪怕只是窗口内手工验证清单）。
2. **子资源无法逐条观测**（见 §4 的诚实边界），只能记录**导航级**出网。
3. 独立数据存储：`WKWebsiteDataStore.nonPersistent()`（或独立持久化目录），**不与客户端数据混放**。

**实际实现要点（2026-09-23）**
   ① `explicitLoadRequested` 标记 —— 地址栏导航在 `WKWebView` 里落成 `navigationType == .other`，
      与「脚本自己发起的跳转」同类。**只靠 navigationType 判断会二选一地弄坏**：要么挡住地址栏（功能坏），
      要么放过脚本跳转（安全属性坏）。所以由应用层显式标记「这是用户按的」，且该标记**用一次即失效**；
   ② `.other` 一律**不算**用户发起（宁可拦掉、让用户手动点一次，也不让「默认不加载远程内容」失效）；
   ③ 不注册任何 `WKScriptMessageHandler`（网页没有通往客户端能力的桥）；
   ④ **放行与拦截都写外发日志**（拦截也留痕，见 `denied` 语义）。

**验证状态（如实）**：编译通过（平台模块随 `swift test` 构建）；**运行时行为未验证** ——
需要在 GUI 里按手工清单走一遍：默认页签不出网 / 地址栏导航可用 / 点链接可用 / 脚本跳转被拦 /
后退前进 / 下载走授权目录。

## 3. 页签模型集成（App 层）· 已完成

现状：`AppState.tabs: [QueryTab]`，被约 100 处引用 —— **不能**直接把浏览器塞进 `QueryTab`（会把 SQL 专属字段污染成可选堆）。

推荐做法（改动面最小、语义最清楚）：

1. 新增 `Core/EditorTabRef`（或 `BrowserTab` 列表 + 一个 `EditorSelection` 枚举）：
   ```swift
   enum EditorSelection: Hashable { case query(UUID); case browser(UUID) }
   ```
2. `AppState` 增 `@Published var browserPages: [BrowserPage]` 与 `selectedEditorTab: EditorSelection`；
   `tabs` 保持原样（SQL 路径零改动）。
3. 页签条渲染两段：SQL 页签（现有）+ 浏览器页签（新），选中态共用同一套令牌与交互；
   关闭 / 新建 / 切换都走 `selectedEditorTab`。
4. 编辑器区按选中类型渲染：SQL → 现有 `QueryEditorView`；浏览器 → 新的 `BrowserTabView`
   （地址栏 + 前进后退刷新 + 引擎视图 + 加载态/错误条）。
5. 会话持久化：`browserPages` 随会话恢复（契约要求"可关闭可恢复"），恢复时**不自动重放导航**
   （与"默认不加载远程内容"一致：恢复出来的是地址与标题，要用户按回车才真正加载）。

## 4. 诚实边界（需要记进需求书，不能含糊过去）

| 项 | 事实 | 处置 |
|---|---|---|
| **子资源不可观测** | `WKWebView` 的公开 API **不暴露**单个子资源请求（只有主框架/iframe 导航与下载）。因此"每条子资源都进日志"在当前引擎下做不到 —— 除非自建本地代理（体量与风险都不合适） | 把 NFR-SEC-08 的验收改成"**引擎可观测的出网**：导航级 + 下载级"，并在 FR-EDIT-34 的证据列写明该限制；不假装做到了 |
| 下载 | 走 `WKDownloadDelegate`；落地必须经**授权目录**（`SecureDirectoryAccess`） | 与 FR-AI-08 同一套 |
| 页面脚本不得触达客户端能力 | 不注册任何 `WKScriptMessageHandler`（不注入脚本桥） | 写进实现注释与回归清单 |
| 跨平台 | 引擎可换（WKWebView / WebKitGTK / 其他）；**策略与日志格式不可换** | 契约在 Core，已在测试里钉住 |
